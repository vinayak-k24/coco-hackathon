## Context

Two root problems:
1. **Backend: No connection reuse** — `db.py` creates a new Snowflake connection on every single query with `externalbrowser` auth, which opens a browser popup each time and causes 500 errors or extreme slowness. Every API call from 14 components fails → frontend shows blanks.
2. **Frontend: No error resilience** — `fetchApi` throws on any non-200 response. Components catch but leave state as `null`, rendering blank cards with no loading/error feedback.

## Implementation Steps

### 1. Fix `Backend/db.py` — Connection pool with token caching
- Create a module-level cached connection (singleton pattern)
- Reuse the same connection across requests instead of creating one per query
- Add retry logic: if connection is stale/closed, reconnect once
- This makes `externalbrowser` auth pop up only once on first request

### 2. Fix `Backend/main.py` — Add exception handler
- Add a global exception handler so 500 errors return JSON instead of HTML
- Add logging so errors are visible in the terminal

### 3. Fix `Frontend/lib/api.ts` — Graceful error handling
- Make `fetchApi` return `null` on failure instead of throwing
- Add a `fetchApiOrDefault<T>(path, defaultValue)` helper so components always have fallback data
- Or: wrap fetch in try-catch and return a default

### 4. Fix all 14 frontend components — Show loading state + handle null data
- Add loading state so cards show "Loading..." instead of blank
- Use default values when API data is null

## Critical Files
- `Backend/db.py` — Fix connection pooling (root cause)
- `Backend/main.py` — Add error logging/handler
- `Frontend/lib/api.ts` — Add error-resilient fetch
- `Frontend/components/KpiMetricsRow.tsx` — Pattern for loading state (apply to all 14)
