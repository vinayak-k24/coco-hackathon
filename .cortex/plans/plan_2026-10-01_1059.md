### Implementation Steps

**Step 1: Core infrastructure** (`config.py`, `db.py`, `main.py`, `requirements.txt`, `.env.example`)
- `config.py`: Pydantic Settings with SF account, user, warehouse, database=PDM, authenticator=externalbrowser
- `db.py`: Connection factory using `snowflake.connector.connect()` with externalbrowser. Helper `execute_query(sql, params)` that returns list of dicts. Graceful handling when PDM database/tables don't exist yet (catch `ProgrammingError`, return empty results).
- `main.py`: FastAPI app with CORS (allow `localhost:3000`), mount all route modules, lifespan for connection warmup
- `requirements.txt`: `fastapi`, `uvicorn[standard]`, `snowflake-connector-python`, `pydantic-settings`, `sse-starlette`, `python-dotenv`

**Step 2: Response models** (`models/responses.py`)
- Pydantic models matching the TypeScript interfaces: `KpiSummary`, `PlantHealth`, `AlertItem`, `OrderAtRisk`, `AssetDetail`, `SensorReading`, `MaintenanceQueueItem`, `SupplyChainItem`, `ProductionDay`, `EnergyPlant`, `TechnicianSummary`, `ActivityEvent`, `FinanceSummary`, `Incident`, `IncidentOption`, `IncidentAction`

**Step 3: Dashboard routes** (all GET, query RAW tables directly since ANALYTICS views don't exist yet)
- Each route: connect to Snowflake, run SQL against `PDM.RAW.*` tables, shape into response model, return JSON
- SQL queries are inline but structured — they'll be moved to views later when `09_views.sql` is built
- If PDM doesn't exist, return sensible empty responses (not 500s)

**Step 4: Incident lifecycle routes** (`routes/incidents.py`)
- REST endpoints for CRUD on `APP.INCIDENTS`, `APP.INCIDENT_OPTIONS`, `APP.INCIDENT_ACTIONS`
- SSE endpoint (`/api/incidents/{id}/stream`) using `sse-starlette` — polls `APP.INCIDENT_EVENTS` every 2s, pushes new events
- Approve endpoint that calls `SP_EXECUTE_OPTION` (stub if SP doesn't exist yet)

**Step 5: Copilot routes** (`routes/copilot.py`)
- `POST /api/copilot/chat` — proxy to Cortex Agent API (Snowflake REST). Streams response tokens via SSE.
- `POST /api/copilot/explain-alert` — calls SP or agent for cited root cause
- Fallback: if Cortex Agent not available, use `SNOWFLAKE.CORTEX.COMPLETE()` with a system prompt + context SQL

**Step 6: Simulator routes** (`routes/simulator.py`)
- `POST /api/sim/start` — placeholder that sets simulator state (in-memory for now)
- `POST /api/sim/action`, `POST /api/sim/reset`, `GET /api/sim/status`
- Real simulator logic comes later when scenario scripts are built

### Key Design Decisions
- **SQL in routes (not views)**: Since `PDM` database and analytics views don't exist yet, routes contain raw SQL against `PDM.RAW.*`. When views are built, we swap the SQL.
- **Graceful degradation**: Every route catches `ProgrammingError` (table doesn't exist) and returns empty data rather than 500.
- **Connection per request**: For hackathon simplicity, create connection per request (not pooled). Externalbrowser caches the token after first login.
- **Currency**: All amounts returned in INR. Frontend will format with `Intl.NumberFormat('en-IN')`.
